# Scooter Blender authoring

Read the root `AGENTS.md`, the current authority in `../../docs/ride-lab/PROJECT_STATE.md`, and [the skill guidance map](docs/SKILL_GUIDANCE.md) before work. Current user instructions override historical approvals and examples.

Use this package for new scooter authoring. Keep model edits, generated targets and visual reviews distinct. A review request alone does not authorize edits. Preserve approved milestones and unrelated work; do not migrate or delete historical assets as routine cleanup.

Keep reviewer input narrow and independent: target, frozen candidate images, comparison conditions and acceptance criteria. Supply prior issues after the initial independent comparison. Do not include the implementer's preferred diagnosis in the first review.

Load only phase-relevant skill references. Runtime export, UV work, materials, rigging and physical fitting begin when included in the authorized phase. Keep one compact current note for each study, with evidence paths, stable issue IDs, failed hypotheses and the next decisive check.

Native models and preview renders are ignored by default. Keep unique source work recoverable and track selected references, scripts, review notes and acceptance records. Approval and exact-file verification are required before promoting a candidate to a milestone.
