# rideLab Phases 1–2 verification

`/mall/ride-lab` is an explicitly gated development laboratory for Jolt's native
`MotorcycleController`. It is not linked from the mall and cannot be enabled by
`MALL_ENABLED`. The production proxy returns HTTP 404 even when
`RIDE_LAB_ENABLED=true`; local development requires that dedicated flag.

## Architecture

- `JoltRidePhysics.ts` owns the Jolt interface, two-wheel motorcycle constraint,
  arena colliders, fixed-step input resolution, canonical diagnostics, reset,
  and explicit WASM teardown.
- `RideLabRuntime.ts` owns Three.js rendering, camera and speed feedback,
  keyboard/touch input, context loss, resizing, cancellation-safe reconfigure,
  and observable lifecycle counters.
- `rideLabVehicleVisual.ts` is the Ride-Lab-only adapter for the curated CC0
  scooter and skater rider. It owns asset loading/fallback, semantic toon
  replacement, stable wheel and steering pivots, moving grip targets, additive
  rider-bone pose, grip/seat contact metrics, and idempotent Three.js disposal.
  Outside-elbow flare, inside-arm tuck, shoulder yaw, head counter-lean, and
  throttle head tuck all derive from the canonical smoothed intent rather than
  a second animation timeline. It must not be imported by the authored `/mall`
  runtime.
- `rideLabTuning.ts` owns the complete versioned Phases 1–2 configuration, bounds,
  presets, sanitation, and import/export format.
- `RideLabExperience.tsx` owns the development UI, categorized controls,
  tooltips/descriptions, telemetry, reduced-motion override, and the single
  `itsmeio.rideLab.config.v12` storage key. Older configuration keys are removed
  so obsolete handling defaults cannot silently override the current lab.
- The existing Rapier `/mall` runtime, authored scene, copy, and route gate are
  unchanged. `proxy.ts` adds only the independent nested-lab boundary.

## Automated evidence

Run:

```text
npm run test:ride-lab
npm run test:mall
npm run typecheck
npm run lint:ride-lab
npm run verify:ride-lab:assets
npm run verify:ride-lab
npm run build
npm run verify:ride-lab:production
node scripts/verify-ride-lab-evidence.mjs
```

Focused tests prove exact repeat-run determinism, native-controller identity,
throttle spool, momentum after release, braking, monotonic steering recovery,
ground–air–ground ramp travel, preload/release ollies, bounded hover resource,
wall-grind momentum, safe configuration parsing, route isolation, and idempotent
Jolt memory cleanup. The asset verifier pins the exact curated output hashes,
required movable nodes and rider bones, payload bounds, and provenance ledger.
Browser verification covers the complete contextual Space
journey, first-frame input acknowledgement, braking load transfer, tuning
metadata/persistence, seated contact within 1 cm, hands within 8 cm of their
grips at rest and through full steering, asymmetric outside-elbow flare,
mirrored shoulder/head response, aligned handlebar/front-wheel steering,
gradual visual recovery, travel-driven wheel spin, WebGL
loss and restoration, repeated reloads, reduced motion, touch controls, and
375×812 layout without horizontal overflow. The precise aerial contract lives
in `ride-lab-aerial.md`.

The checked-in measurement artifact is regenerated by the browser verifier and
is the exact 2026-08-28 headless Chromium reference. Its budgets are:

| Measure | Budget |

These are regression and lifecycle oracles, not subjective approval.

## Human promotion gates

A person must still judge motorcycle weight, steering recovery, skid feel,
camera composition, speed feedback, ollie timing, hover generosity, grind
readability, arena readability, scooter scale/orientation, seated silhouette,
rider pose, three-band shading, outline weight, wheel motion, rematerialization,
and fit with the mall's authored
direction. Audio, promotion into `/mall`, and further assets remain separate
work.

## Durable agent context

Future agents should preserve the independent non-production route boundary and
the unchanged Rapier baseline. Add new physical concepts to the canonical
snapshot before connecting feedback consumers, keep advanced Jolt values
separate from semantic controls, add deterministic envelopes for every promoted
mechanic, explicitly destroy every Emscripten-owned object, and never present a
handling/camera/art judgment as automated approval. Keep source archives out of
the repository, update `mall-asset-provenance.md` plus the pinned asset verifier
when a curated output changes, retain seat/grip budgets as placement regression
oracles, and preserve a usable procedural fallback for asset-load failure.
